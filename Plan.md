# Памятка по лабораторной работе №4

Основа: `laba4.doc`, тема «Ввод-вывод. Обработка файлов». Здесь — порядок работы и краткий справочник Java для выполнения задания на примере вашей модели транспорта.

**Обозначения:** `()` — параметров нет; `void` — метод ничего не возвращает; `boolean` — `true` или `false`; `String` — строка; `int`/`long` — целое число; `List<Vehicle>` — список транспорта. В Java функции обычно называют методами. `new` вызывает конструктор и создаёт объект.

## 1. Что нужно сделать

1. Взять модель и демонстрационную программу из ЛР №2. В ЛР №3 уже есть полезные классы транспорта и коллекций.
2. При старте читать настройки: логин, пароль, группу, флаги отладки и автотестов.
3. Запрашивать логин и пароль; при успехе выводить приветствие с именем пользователя.
4. Добавить меню чтения, записи, добавления, изменения и удаления объектов.
5. Сохранять **несколько объектов** в обычном текстовом файле и восстанавливать их типы и поля.
6. Для `root` показывать дополнительные пункты «Отладка» и «Автотесты».
7. При `debug=true` писать отладочные данные независимо от группы пользователя.
8. При `autotests=true` выполнять автотесты до главного меню, выводить результат на консоль и в лог.
9. Лог дописывать, снабжать записи временем. Отмечать старт с логином, операции с файлом базы, ошибки, результаты тестов и завершение.

Уникальный ID объекта рекомендован методичкой: по нему удобно искать, менять и удалять запись. SQL и сервер базы данных здесь не требуются.

## 3. Настройки и вход

Пример **предлагаемого** файла `laba4/config.properties`; имена ключей выбираете сами:

```properties
login=student
password=1234
group=root
debug=true
autotests=true
db.file=data/vehicles.txt
log.file=logs/app.log
```

Первые пять настроек нужны по заданию; пути к базе и логу добавлены для удобства. В `group` допустимы `root` и `user`.

| Готовый API Java | Описание и параметры |
| --- | --- |
| `new Properties()` | Создать набор строковых настроек (`java.util.Properties`). |
| `props.load(Reader reader)` | Загрузить `ключ=значение`; `reader` — символьный поток. |
| `props.load(InputStream input)` | Загрузить из байтового потока; этот вариант использует ISO-8859-1, для UTF-8 удобнее `Reader`. |
| `props.getProperty(String key)` → `String` | Получить значение ключа; если его нет — `null`. |
| `props.getProperty(String key, String defaultValue)` → `String` | Получить значение или заданное значение по умолчанию. |
| `Boolean.parseBoolean(String value)` → `boolean` | Превратить строку `"true"` в `true`; прочие значения дадут `false`. |
| `Integer.parseInt(String value)` → `int` | Превратить строку в число; неверный формат вызывает `NumberFormatException`. |
| `Integer.valueOf(String value)` → `Integer` | Аналогичное преобразование, но возвращает объект `Integer`. |
| `Settings.class.getResourceAsStream(String name)` → `InputStream` | Открыть ресурс из classpath, в том числе JAR; отсутствие ресурса даёт `null`. |
| `new Scanner(System.in)` | Создать средство чтения консоли (`java.util.Scanner`). |
| `scanner.nextLine()` → `String` | Прочитать введённую строку. Удобно и для меню, и для полей. |
| `actual.equals(String expected)` → `boolean` | Сравнить содержимое строк; `actual` не должен быть `null`. |
| `System.out.println(Object value)` | Напечатать значение с переводом строки. |

`getResourceAsStream("config.properties")` ищет рядом с классом; `getResourceAsStream("/config.properties")` — от корня classpath. Внешний файл удобнее читать по обычному пути. Относительные пути считаются от рабочей папки запуска.

Порядок запуска: загрузить и проверить настройки → открыть лог → запросить учётные данные → проверить вход → записать старт с логином → при нужном флаге выполнить тесты → показать меню. При неверном входе не открывать главное меню.

## 4. Текстовая база и операции со списком

Простой предлагаемый формат: одна строка — один объект, поля разделены `;`:

```text
1;Car;470;1800;55;SAFE
2;Truck;1100;11000;35;FLAMMABLE
```

Поля: `id;тип;габарит;масса;скорость;категорияГруза`. При чтении по типу создать `Car`, `Truck`, `Bus`, `Trailer` или `CarWithTrailer`. Названия типов и категорий должны совпадать с выбранным форматом.

| Готовый API Java | Описание и параметры |
| --- | --- |
| `line.split(String regex, int limit)` → `String[]` | Разделить строку; для этого формата `line.split(";", -1)` сохраняет пустые поля. |
| `text.trim()` → `String` | Убрать пробелы по краям. |
| `text.isEmpty()` → `boolean` | Проверить, пуста ли строка. |
| `Long.parseLong(String value)` → `long` | Прочитать числовой ID. |
| `CargoClass.valueOf(String name)` → `CargoClass` | Найти константу перечисления по точному имени; неизвестное имя — ошибка. |
| `new ArrayList<Vehicle>()` | Создать изменяемый список (`java.util.ArrayList`). |
| `list.add(Vehicle vehicle)` → `boolean` | Добавить объект в конец списка. |
| `list.get(int index)` → `Vehicle` | Получить объект по индексу, начиная с `0`. |
| `list.set(int index, Vehicle vehicle)` → `Vehicle` | Заменить объект; возвращает прежний объект. |
| `list.remove(int index)` → `Vehicle` | Удалить объект по индексу. |
| `list.removeIf(Predicate<Vehicle> condition)` → `boolean` | Удалить подходящие объекты: `list.removeIf(v -> v.getId() == id)`. |
| `list.size()` → `int` | Получить число объектов. |
| `list.clear()` → `void` | Очистить список перед полной заменой загруженными данными. |
| `list.addAll(Collection<? extends Vehicle> items)` → `boolean` | Добавить все элементы другой коллекции. |

**ID и индекс — разные вещи:** ID сохраняется в файле, индекс меняется после удаления элементов.

Порядок операций:

- **Чтение:** прочитать строки во временный список → проверить поля, типы и уникальность ID → заменить текущий список → показать объекты на консоли.
- **Добавление:** ввести один или несколько объектов → назначить свободные ID → добавить к текущим данным → сохранить.
- **Изменение:** найти ID → запросить новые поля → заменить данные → сохранить.
- **Удаление:** найти ID → удалить запись → сохранить.
- **Запись:** записать актуальный список целиком. Сначала загрузить существующие записи, если их нужно сохранить.

Для изменения и удаления проще переписывать весь файл базы. **Лог**, наоборот, всегда дописывается. Отдельные пункты чтения и записи должны присутствовать в меню.

## 5. Чтение и запись файлов

Байтовый поток работает с байтами; символьный — с текстом. Для базы, настроек и лога удобно явно использовать UTF-8.

### Основные классы для выполнения задания

| Конструктор или метод | Описание и параметры |
| --- | --- |
| `new FileInputStream(String path)` | Открыть файл для чтения байтов; `path` — путь. |
| `new FileInputStream(File file)` | То же, но путь представлен объектом `File`. |
| `new FileOutputStream(String path, boolean append)` | Открыть запись байтов; `true` — дописывать, `false` — перезаписывать. |
| `new InputStreamReader(InputStream input, Charset charset)` | Преобразовать байты в символы; `charset` — кодировка. |
| `new OutputStreamWriter(OutputStream output, Charset charset)` | Преобразовать символы в байты выбранной кодировки. |
| `StandardCharsets.UTF_8` | Готовая константа кодировки (`java.nio.charset.StandardCharsets`). |
| `new BufferedReader(Reader reader)` | Добавить буфер и чтение строк к символьному потоку. |
| `reader.readLine()` → `String` | Прочитать строку без перевода строки; конец файла — `null`. |
| `new BufferedWriter(Writer writer)` | Добавить буфер к записи текста. |
| `writer.write(String text)` → `void` | Записать строку; перевод строки сам не добавляется. |
| `writer.newLine()` → `void` | Записать перевод строки. |
| `writer.append(CharSequence text)` → `Writer` | Записать текст; дописывание **в файл** определяется режимом открытия файла. |
| `writer.flush()` → `void` | Отправить накопленные символы дальше из буфера. |
| `stream.close()` → `void` | Закрыть поток и освободить ресурс; выходной поток также завершает запись. |
| `new FileReader(String path)` | Простой текстовый ввод с кодировкой по умолчанию. |
| `new FileWriter(String path, boolean append)` | Простой текстовый вывод с кодировкой по умолчанию. |

Основные классы потоков находятся в `java.io`. `InputStreamReader`/`OutputStreamWriter` также принимают имя кодировки строкой, например `"UTF-8"`.

Пример чтения UTF-8; `path` — переменная с путём к файлу:

```java
try (BufferedReader reader = new BufferedReader(
        new InputStreamReader(new FileInputStream(path), StandardCharsets.UTF_8))) {
    String line;
    while ((line = reader.readLine()) != null) {
        // Разобрать line и добавить объект во временный список.
    }
}
```

Пример **дописывания лога**; для полной записи базы заменить `true` на `false`:

```java
try (BufferedWriter writer = new BufferedWriter(
        new OutputStreamWriter(new FileOutputStream(path, true), StandardCharsets.UTF_8))) {
    writer.write("Сообщение");
    writer.newLine();
}
```

### Проверка путей через `java.io.File`

| Конструктор или метод | Описание и параметры |
| --- | --- |
| `new File(String path)` | Создать объект пути; сам файл на диске не создаёт. |
| `new File(String parent, String child)` | Соединить путь папки и имя файла; есть вариант с `File parent`. |
| `exists()`, `canRead()`, `canWrite()` → `boolean` | Проверить существование и доступность; параметров нет. |
| `isFile()`, `isDirectory()`, `isAbsolute()` → `boolean` | Проверить обычный файл, каталог или абсолютность пути. |
| `getName()`, `getPath()`, `getAbsolutePath()`, `getParent()` → `String` | Получить имя, путь, абсолютный путь или родительскую папку. |
| `getParentFile()` → `File` | Получить родительскую папку объектом; может вернуть `null`. |
| `mkdir()`, `mkdirs()` → `boolean` | Создать папку; `mkdirs()` также создаёт недостающие родительские папки. |
| `length()` → `long` | Размер файла в байтах. |
| `lastModified()` → `long` | Время изменения в миллисекундах с начала Unix-эпохи. |
| `renameTo(File target)` → `boolean` | Переименовать или переместить файл к пути `target`. |
| `delete()` → `boolean` | Удалить файл или пустую папку. |
| `list()` → `String[]` | Получить имена содержимого папки; при ошибке может вернуть `null`. |
| `list(FilenameFilter filter)` → `String[]` | Получить имена по фильтру; его метод `accept(File dir, String name)` решает, включать ли имя. |
| `File.separator`, `File.pathSeparator` | Разделитель частей пути и разделитель списка путей соответственно; это поля, не методы. |

Перед записью `data/vehicles.txt` и `logs/app.log` нужно создать папки `data` и `logs`, если их ещё нет.

## 6. Логи, ошибки и автотесты

| API или конструкция | Описание и параметры |
| --- | --- |
| `LocalDateTime.now()` → `LocalDateTime` | Текущая дата и время (`java.time.LocalDateTime`). |
| `DateTimeFormatter.ofPattern(String pattern)` → `DateTimeFormatter` | Создать формат времени, например `"yyyy-MM-dd HH:mm:ss"`. |
| `dateTime.format(DateTimeFormatter formatter)` → `String` | Получить время строкой по формату. |
| `try (ресурс = ...) { ... }` | Автоматически закрыть ресурс, в том числе при ошибке. |
| `catch (IOException e)` | Обработать ошибку чтения или записи. |
| `catch (NumberFormatException e)` | Обработать неверно введённое число. |
| `throw new IllegalArgumentException(String message)` | Сообщить о недопустимых данных. |
| `throws IOException` | В объявлении метода: передать обработку ошибки вызывающему коду. |
| `e.getMessage()` → `String` | Получить краткое описание ошибки. |
| `e.printStackTrace()` → `void` | Вывести подробности в стандартный поток ошибок; в файл лога сам по себе не пишет. |
| `System.err.println(String message)` | Напечатать сообщение об ошибке в консоль. |

Пример записи: `2026-10-25 18:30:00 INFO login=student: загружено 5 объектов`.

Флаг `debug` управляет дополнительными контрольными данными. Обязательные события и результаты автотестов удобно писать всегда, чтобы они не терялись при выключенной отладке. Права `root` определяют видимость пунктов меню, а флаги настроек — автоматическое выполнение при старте.

Минимальные автотесты, которые стоит реализовать:

- Сохранить несколько объектов разных типов → загрузить → сравнить число, ID, типы и все поля.
- Добавить записи → проверить, что прежние записи сохранились, ID не повторяются.
- Изменить по ID → проверить новые поля и неизменность остальных объектов.
- Удалить по ID → проверить отсутствие объекта после повторного чтения файла.
- Проверить неверный ID, повреждённую строку и отсутствующий файл.
- Проверить вход, права `root`/`user` и поведение флагов.
- Дважды открыть лог → убедиться, что прежние записи остались и у новых есть время.

Для тестов использовать отдельный файл базы. Успех проверки — сравнение результата с ожидаемым значением, а не только отсутствие исключения.

## 7. Дополнительный справочник по теории методички

### Байтовые потоки и произвольный доступ

| API | Краткое описание и параметры |
| --- | --- |

| `input.read()` → `int` | Прочитать один байт: `0..255`, конец потока — `-1`. |
| `input.read(byte[] buffer)` → `int` | Заполнить буфер; вернуть число байтов или `-1` в конце. |
| `input.read(byte[] buffer, int off, int len)` → `int` | Прочитать до `len` байтов в массив начиная с индекса `off`. |
| `input.skip(long count)` → `long` | Пропустить до `count` байтов; вернуть фактическое число. |
| `input.available()` → `int` | Оценить байты, доступные без блокировки; это не размер файла и не проверка конца. |
| `output.write(int b)` → `void` | Записать младшие 8 бит числа. |
| `output.write(byte[] buffer)` → `void` | Записать весь массив байтов. |
| `output.write(byte[] buffer, int off, int len)` → `void` | Записать ровно `len` байтов с индекса `off`; диапазон должен быть допустимым. |
| `new BufferedInputStream(InputStream input)` | Буферизовать чтение байтов; второй необязательный аргумент `int size` — размер буфера. |
| `new BufferedOutputStream(OutputStream output)` | Буферизовать запись байтов; также можно передать `int size`. |
| `new RandomAccessFile(String path, String mode)` | Открыть файл с произвольным доступом: `"r"` — читать, `"rw"` — читать и писать. Есть вариант с `File`. |
| `raf.seek(long pos)` → `void` | Перейти на позицию `pos` в **байтах** от начала файла. |
| `raf.getFilePointer()` → `long` | Получить текущую позицию. |
| `raf.length()` → `long` | Получить размер файла в байтах. |
| `raf.read()`, `raf.write(int b)`, `raf.close()` | Читать байт, писать байт, закрывать файл. |
| `stream.getFD()` → `FileDescriptor` | Получить дескриптор у файлового потока или `RandomAccessFile`; у `File` такого метода нет. |
| `reader.getEncoding()`, `writer.getEncoding()` → `String` | Получить имя кодировки у `InputStreamReader`/`OutputStreamWriter`. |

`RandomAccessFile` реализует интерфейсы `DataInput` и `DataOutput`; это не наследник `InputStream`/`OutputStream`. Приведённый в методичке конструктор `RandomAccessFile(FileDescriptor)` не следует использовать: такого публичного конструктора нет.

## 8. Команды сборки и запуска

Команды ниже — для **PowerShell**, после реализации программы. Нужен установленный JDK, команды `java` и `javac` должны быть доступны в `PATH`. Пример предполагает обычный класс `Main` без `package`, с точкой входа `public static void main(String[] args)`.

```powershell
# Перейти из корня репозитория в проект лабораторной.
Set-Location .\laba4

# Узнать версии среды выполнения и компилятора.
java -version
javac -version

# Создать папки, если их ещё нет.
New-Item -ItemType Directory -Force out, data, logs

# Собрать все исходники, включая подпапки.
$labSources = @(Get-ChildItem -Path .\src -Recurse -Filter *.java | ForEach-Object { $_.FullName })
javac -encoding UTF-8 -d out $labSources

# Запустить с рабочей папкой laba4.
java -cp out Main
```

| Команда или параметр | Значение |
| --- | --- |
| `Set-Location путь` | Сменить рабочую папку. |
| `New-Item -ItemType Directory -Force имена` | Создать перечисленные папки; существующие сохранить. |
| `Get-ChildItem -Path путь -Recurse -Filter *.java` | Найти Java-файлы во всех подпапках. |
| `javac -encoding UTF-8 -d out файлы` | Скомпилировать исходники UTF-8 в папку `out`. |
| `java -cp out Main` | Искать классы в `out` и запустить `Main`. |

Если у `Main` появится `package app;`, запускать `java -cp out app.Main`. Для внешнего `config.properties` положить файл в папку `laba4`. При загрузке через ресурс его нужно дополнительно скопировать в соответствующее место в `out`; `javac` ресурсы не копирует.

## 9. Частые ошибки

- Сравнивать строки через `.equals()`, а не `==` или `!=`.
- Конец `readLine()` — `null`; пустая строка `""` ещё не означает конец файла.
- Для условий с проверкой `null` использовать `&&`: он не вычисляет вторую часть, если первая ложна.
- Закрывать потоки через `try-with-resources`, не рассчитывать на сборщик мусора.
- При чтении и записи выбирать одну кодировку, иначе кириллица может испортиться.
- Проверять число полей, числа, тип транспорта и повторяющиеся ID до замены текущих данных.
- Не открывать лог с `append=false`: это сотрёт предыдущие записи.
- Не использовать индекс списка как постоянный ID объекта.
- `flush()` отправляет данные из буфера, но сам по себе не гарантирует физическую запись на диск.
- Примеры методички содержат опечатки: `IOExceptioon` нужно заменить на `IOException`, а `_string1` в примере подсчёта слов — согласовать с объявленным `_string`.
